One theme across every surface

1. First visit

Use the device theme before visible content paints.

2. Choose Light or Dark

Apply immediately and remember the choice in this browser.

3. Move around

Login, account pages, dialogs, menus, and notifications use the same appearance.

A concrete example

A device starts in Dark. The user selects Light, visits Audit log, then reloads. The dashboard stays in Light; later device changes leave the saved choice in place.

Verification boundary

The implementation must preserve login, logout, history, and account operations. The preview does not connect to credentials or a server. Production theme startup, accessibility, and viewport behavior will be checked against the integrated application.

Terms and limits

Device theme means the operating system appearance preference. Drawer means the small-screen navigation opened by the menu button. This sketch previews layout and behavior; it is not a pixel-perfect replacement of the existing account cards.

Design brief: Product register; local developer tool on desktop and narrow windows; calm, dense slate surfaces with one blue accent; system fonts; a persistent bottom account section; variance 3, motion 1, density 6. Existing dark tokens are retained; accessible light tokens are added. The workflow diagram is compiled locally from typed IR, with no external assets.
